# CONTEXT.md — Comfort Clinic Check-up Quiz

Документ для разработчика и AI-кодинг-агента. Содержит устойчивые технические факты, текущую архитектуру и правила изменения проекта. Обновляй его после существенных изменений логики, каталога, связей с Tilda или способа развёртывания.

## 1. Назначение и границы

Проект: **интерактивный подбор существующих программ обследования Comfort Clinic**. Основа — пятишаговый квиз с условной навигацией и показом до трёх карточек каталога.

- Репозиторий: https://github.com/DiasMazhenov/comfortclinic-checkup-quiz
- Сайт: https://comfortclinic.kz
- Целевой адрес: https://comfortclinic.kz/checkup
- В исходном ТЗ встречался **/checkups**. По проверке Tilda MCP фактический URL страницы в проекте — **/checkup**; не предполагай автоматический редирект.
- Технология: **Tilda T123** с inline HTML/CSS/JavaScript (ES6, без бэкенда).
- Исходные данные: 16 существующих Tilda Zero Blocks, представленных в локальном JSON.
- Ограничение: подбор отражает **структуру каталога**, а не врачебную диагностику по симптомам.

Важно: Github и Tilda — **разные состояния**. Коммит не меняет блок в редакторе, а сохранение блока не публикует страницу автоматически. Не утверждай, что версия работает публично, без отдельной проверки.

## 3. Вкладки и связь с карточками

Существующий блок ME602A содержит нативную конфигурацию **li_blocks** и управляет видимостью секций через JS Tilda **t1281**. Вкладки:

| Индекс | Имя | Количество T396 |
| --- | --- | ---: |
| 1 | Женский | 3 |
| 2 | Мужской | 2 |
| 3 | Общий | 4 |
| 4 | Детский | 7 |

Из T123 используй URL-хеш **#!/tab/5299319803-N** для вкладки N, затем обнаружение блока **#rec<recordId>** и скролл только после того, как блок виден. Не управляй display секций вручную и не меняй t1281__off: это ответственность Tilda. На мобильном представлении Tilda использует select, поэтому переход к вкладке/карточке требуется тестировать отдельно от desktop.

Нативное событие переключения Tilda: **tildatab:change**. В текущей версии квиза используются программный клик по ссылке вкладки, попытка переключения select, hash и повторная проверка видимости блока (~3,5 с). Это практический механизм, но **не подтверждён автотестом в реальном опубликованном браузере**.

Ссылка ручного выбора: **#rec5299319803**. Она всегда присутствует на пятом шаге и ведёт к текущим четырём вкладкам, а не к новому каталогу.

## 5. Состояние квиза / state machine

Глобальный контейнер: **#cc-quiz**, классы **.ccq***. Инициализация idempotent через **data-mounted**. Вся обработка в IIFE; глобальные переменные не экспортируются.

Состояние: **stage** (0..4), **selection** { sex, age, topic, details } и таймер навигации к выбранному T396.

| stage | Поле | Ввод | Валидация |
| ---: | --- | --- | --- |
| 0 | sex | Женский / Мужской | Одиночный, обязателен |
| 1 | age | Полные годы | Целое 0..100, обязательно |
| 2 | topic | Карточка направления | Один вариант, обязательно |
| 3 | details | Несколько уточнений | Необязательно, пропускается для общего профиля |
| 4 | результаты | До 3 программ | Отображение + ручной каталог |

Возрастные полосы: 0–6, 7–17, 18–34, 35+. Для фильтра используется исходное точное число.

Показываемые темы: общий профиль, ЖКТ, щитовидная железа, лишний вес; взрослым женщинам — гинекология, взрослым мужчинам — урология. Для гинекологии есть выбор из «Подготовка к беременности», «Сбитый цикл», «Менопауза», «Общий гинекологический чекап». Темы являются дополнительными ответами и **не участвуют в вычислении candidates()**. Для остальных категорий уточнения «Состав обследования», «Стоимость», «Подготовка к приёму» носят организационный характер. Текущая UI-копия **не содержит** слов «демо» и «согласование».

Переходы: Вперёд с проверкой обязательных полей; Назад, Сброс. Если пользователь меняет пол/возраст/направление, зависящие от ответа значения очищаются. Общий профиль сразу открывает результаты с третьего экрана (шаг 4 пропущен).

## 6. Вычисление кандидатов и fallback

Функции внутри HTML: **eligiblePrograms()**, **generalPrograms()**, **candidates()**.

Сначала фильтруются записи по точному возрасту и gender. Затем:

1. Если topic=general — возвращаются до трёх general-программ соответствующей возрастной группы.
2. Иначе — поиск прямых совпадений topic среди доступных программ (до 3).
3. Для **gut** прямые совпадения принудительно пустые: в реестре нет отдельной программы ЖКТ.
4. При нуле прямых совпадений — **fallback на generalPrograms()** с прежними возрастом/полом.
5. Если и общий профиль пуст, карточек нет; пользователь по-прежнему может открыть вкладки вручную.

Приоритет общих программ — жёстко заданный порядок, а не модель вероятности или симптомная оценка:

- Взрослые: Базовый метаболический → Профилактика диабета → Диабет 2 типа.
- Дети младше 6: Здоровый ребёнок → Сила иммунитета → Стоп простуда.
- От 6 до 12: Здоровый ребёнок → Подготовка к школе → Здоровый подросток (если проходит возраст).
- От 13 до 17: Здоровый подросток → Половое созревание → Здоровый ребёнок.

Если ID из приоритетного списка недоступен по ageMin/ageMax, программа не должна попадать в результат. Важно не допускать ложного соответствия для несовпадающего пола/возраста.

В выдаче fallback текст объясняет, что отдельная программа выбранного направления не найдена и предлагаются общие программы. **Кнопка «Выбрать чекап самостоятельно» должна быть всегда**, а не только при пустом списке.

## 7. Привязка записи

Форма записи живёт в Footer по якорю **#zapis**. Квиз создаёт ссылку на эту форму, но **не передаёт** выбранную программу, имя, телефон, детали или возраст в форму и не посылает данные на сервер. Текст результата предлагает сообщить название администратору.

При последующей интеграции формы:
- не меняй существующий popup и JS формы без проверки;
- используй поддерживаемые поля Tilda/CRM и получай необходимые согласия;
- не отправляй скрытно ответы о состоянии здоровья и не собирай их в аналитику.

## 8. Архитектура кода / сборка

- [tilda/comfortclinic_quiz_T123.html](tilda/comfortclinic_quiz_T123.html) — единственный файл для вставки, содержит HTML + CSS + JS + 16 программ.
- [data/checkups.json](data/checkups.json) — удобная редактируемая копия справочника.
- [scripts/build.mjs](scripts/build.mjs) — перенос JSON внутрь массива **const programs=...** в HTML. Инвариант: HTML после сборки содержит точно такие же записи, как JSON.
- [scripts/verify.mjs](scripts/verify.mjs) — базовые статические и регрессионные проверки без библиотек.

Команды (Node.js 20+):

~~~bash
node scripts/build.mjs
node scripts/verify.mjs
~~~

Всё работает без локального сервера. Открытие HTML как файла не эквивалентно тесту внутри Tilda, поскольку при этом отсутствуют t1281, li_blocks, все #rec..., #zapis и глобальные стили сайта.

CSS наследует шрифты Tilda, область действия локальная. Desktop/mobile проверяются отдельно, особенно 320–360 px, 650 px, 950 px, 960–1199 px и 1200+ px. Текущие Zero Block имеют свои брейкпоинты (360/1200), ME602A переключается в select около 960 px.

| Взрослый, общий профиль | Прямой результат, без шага уточнений |
| Пустой возраст / -1 / 101 / 8.5 | Ошибка, блокировка шага |
| Изменить пол/возраст после возврата | Очистить несовместимые ответы |
| Нажать «Посмотреть программу» | Переключить нужную вкладку и доскроллить до конкретного #rec |
| Нажать «Выбрать чекап самостоятельно» | Перейти к существующему ME602A |
| Нажать «Записаться» | Открыть #zapis, не обещать отправки заявки |

**Статусы, которые нельзя смешивать:**
- code/static test: JS и JSON читаются, синтаксис/проверки пройдены;
- Tilda editor: сохранён ли новый HTML в конкретном T123;
- browser preview: действительно ли работает UI и скролл;
- public/live: опубликована ли нужная версия и нет ли проблем на телефоне.

До выполнения каждого этапа соответствующий статус **не подтверждён**.

## 11. Известные ограничения / следующий backlog

- Сейчас **детальные подкатегории не участвуют в ранжировании**. Для истинного соответствия «подкатегория → программа» потребуется явно заданная таблица правил и ревизия реестра.
- Для ЖКТ нет отдельной программы, поэтому срабатывает общий fallback.
- Данные цен/состава дублируются в Tilda и GitHub, пока нет автоматизированного синхронизатора. Сборка из JSON синхронизирует только репозиторий.
- Нет интеграции выбора с формой заявки.
- Нет доказанного end-to-end теста в браузере опубликованного сайта. Снимки и тестирование адаптива нужно проводить по реально загруженной странице.
- Возрастные границы программы «Здоровый подросток» и «Половое созревание» содержат 18 лет, а другие детские программы завершаются в 17 лет. Сверяй конкретные метаданные при изменениях.
- Квиз не заменяет исходные карточки и не включает CRUD для чекапов. Текущий набор — 16 программ на странице /checkup.
