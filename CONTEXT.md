# CONTEXT.md — Comfort Clinic Check-up Quiz

Документ для разработчика и AI-кодинг-агента. Содержит устойчивые технические факты, текущую архитектуру и правила изменения проекта. Обновляй его после существенных изменений логики, каталога, связей с Tilda или способа развёртывания.

## 1. Назначение и границы

Проект: **интерактивный подбор существующих программ обследования Comfort Clinic**. Основа — пятишаговый квиз с условной навигацией и показом до трёх карточек каталога.

- Репозиторий: https://github.com/DiasMazhenov/comfortclinic-checkup-quiz
- Сайт: https://comfortclinic.kz
- Целевой адрес: https://comfortclinic.kz/checkup
- В исходном ТЗ встречался **/checkups**. По проверке Tilda MCP фактический URL страницы в проекте — **/checkup**; не предполагай автоматический редирект.
- Технология: **Tilda T123** с inline HTML/CSS/JavaScript (ES6, без бэкенда).
- Исходные данные: 16 существующих Tilda Zero Blocks. На стороне квиза коммерческие значения читаются из DOM этих блоков по точным elem_id; JSON сохраняет только карту источников и правила подбора.
- Ограничение: подбор отражает **структуру каталога**, а не врачебную диагностику по симптомам.

Важно: Github и Tilda — **разные состояния**. Коммит не меняет блок в редакторе, а сохранение блока не публикует страницу автоматически. Не утверждай, что версия работает публично, без отдельной проверки.

## 3. Вкладки и связь с карточками

Существующий блок ME602A содержит нативную конфигурацию **li_blocks** и управляет видимостью секций через JS Tilda **t1281**. Вкладки:

| Индекс | Имя | Количество T396 |
| --- | --- | ---: |
| 1 | Женский | 3 |
| 2 | Мужской | 2 |
| 3 | Общий | 4 |
| 4 | Детский | 7 |

Из T123 используй URL-хеш **#!/tab/5299319803-N** для вкладки N, затем обнаружение блока **#rec<recordId>** и скролл только после того, как блок виден. Не управляй display секций вручную и не меняй t1281__off: это ответственность Tilda. На мобильном представлении Tilda использует select, поэтому переход к вкладке/карточке требуется тестировать отдельно от desktop.

Нативное событие переключения Tilda: **tildatab:change**. В текущей версии квиза используются программный клик по ссылке вкладки, попытка переключения select, hash и повторная проверка видимости блока (~3,5 с). Это практический механизм, но **не подтверждён автотестом в реальном опубликованном браузере**.

Ссылка ручного выбора: **#rec5299319803**. Она всегда присутствует на пятом шаге и ведёт к текущим четырём вкладкам, а не к новому каталогу.

**Не заменяй ID программ произвольными числами**, не выдумывай цены или обследования и не выдавай сокращённый состав за исчерпывающий. Для обновления программы сначала проверяй её текущий Zero Block через MCP.

## 5. Текущая схема квиза / state machine

**Источник схемы:** присланное клиникой изображение «Схема подбора чекапа», 12 ноября 2026. Текущий алгоритм построен по буквенной матрице в **data/recommendation-rules.json**, а каталог из 16 программ находится в **data/checkups.json**. Старый подбор только по `topic` и прежний шаг необязательных уточнений **удалены**.

- Экраны: **0 пол**, **1 полный возраст (целое 0–100)**, **2 направление**, **3 результаты**.
- Ответы в памяти страницы: `selection = {sex, age, topic}`; не отправляются автоматически.
- Группы: 0–17 `child`, 18–34 `adult18_34`, 35–100 `adult35plus`. Возраст 18 → взрослый, 35 → 35+.
- Для детей обоих полов доступны только направления по схеме: `children`, `thyroid`, `weight`, `general`.
- Для взрослых: `general`, `thyroid`, `weight` плюс `gynecology` для женщин / `urology` для мужчин.
- Направление ЖКТ отсутствует в присланной схеме и **не отображается в квизе**. Его нельзя добавлять в интерфейс без изменения схемы.
- После выбора направления результат показывается сразу, без шага 4 с уточнениями. Пользователь может вернуться, изменить ответы или начать заново.

Результат: **до трёх чекапов** + четвёртая карточка **«Собрать свой чекап»** (переход к штатным вкладкам каталога ME602A). Отдельная кнопка **«Выбрать чекап самостоятельно»** сохранена. Это навигация по каталогу, не реальный индивидуальный конструктор услуг.

## 6. Матрица клиники и fallback

| Пол, возраст | Направление | Коды по приоритету |
|---|---|---|
| Женщина 18–34 | Гинекология / Щитовидная / Лишний вес / Общий | A B C / G F B / G F / G F B |
| Женщина 35+ | Гинекология / Щитовидная / Лишний вес / Общий | A B C / G F B / F I H / F B C |
| Мужчина 18–34 | Урология / Щитовидная / Лишний вес / Общий | D E / G F D / G F / F D E |
| Мужчина 35+ | Урология / Щитовидная / Лишний вес / Общий | D E / G F D / F I H / F I D |
| Дети 0–17 | Детские / Щитовидная / Лишний вес / Общий | K1 K4 K5 / K6 K3 K7 / K1 K3 K4 / K1 K3 K4 |

**Операции:**

1. `currentBranch()` определяет ключ дерева по полу/возрасту.
2. `recommendedForTopic(topic)` находит кодовые ID из ветки и переводит их в программы через `recommendationRules.codes`.
3. Результаты фильтруются по `ageMin <= age <= ageMax` и `gender`, порядок клиники сохраняется, выводится максимум 3.
4. `candidates()` при нуле подходящих позиций ищет те же правила для `general`.
5. При отсутствии даже общих чекапов показывается карточка самостоятельного выбора.

**Примечания по схеме:** Для детей 0–18 лет, 18–35 и 35+ были пересекающиеся границы. Принята однозначная реализация 0–17 / 18–34 / 35+. Для программ с индивидуальными возрастными рамками фильтр `ageMin/ageMax` имеет приоритет над матрицей. Например, K6 — 13–18; K3 — 11–18; K7 — 10+. Не обещай их ребёнку 5 лет. Программа K2 «Подготовка к школе» остаётся в полном каталоге, хотя в конкретных новых ветках схемы не используется.

**Добавление новых чекапов в будущем:**
- Создать нативную карточку T396 в нужной вкладке Tilda; получить её Record ID и фактические данные.
- Добавить запись в `data/checkups.json`, код и Record ID в `data/recommendation-rules.json` → `codes`, соответствующий код в `branches`.
- Пересобрать `npm run build` и выполнить `npm test`.
- Обновить существующий T123 в Tilda и опубликовать только после проверки.
- Изменение `topic` без добавления кода в матрицу **не делает** новую программу рекомендованной.

## 7. Привязка записи

Форма записи живёт в Footer по якорю **#zapis**. Квиз создаёт ссылку на эту форму, но **не передаёт** выбранную программу, имя, телефон, детали или возраст в форму и не посылает данные на сервер. Текст результата предлагает сообщить название администратору.

При последующей интеграции формы:
- не меняй существующий popup и JS формы без проверки;
- используй поддерживаемые поля Tilda/CRM и получай необходимые согласия;
- не отправляй скрытно ответы о состоянии здоровья и не собирай их в аналитику.

## 8. Архитектура кода / сборка

- [tilda/comfortclinic_quiz_T123.html](tilda/comfortclinic_quiz_T123.html) — единственный файл для вставки, содержит HTML + CSS + JS + 16 программ.
- [data/checkups.json](data/checkups.json) — удобная редактируемая копия справочника.
- [scripts/build.mjs](scripts/build.mjs) — сборка минимального массива программ (ID/вкладка/пол/возраст/название для сопоставления), матрицы и `data/tilda-source-map.json`. Значения price/oldPrice/services в T123 не встраиваются.
- [scripts/verify.mjs](scripts/verify.mjs) — базовые статические и регрессионные проверки без библиотек.

Команды (Node.js 20+):

~~~bash
node scripts/build.mjs
node scripts/verify.mjs
~~~

Всё работает без локального сервера. Открытие HTML как файла не эквивалентно тесту внутри Tilda, поскольку при этом отсутствуют t1281, li_blocks, все #rec..., #zapis и глобальные стили сайта.

CSS наследует шрифты Tilda, область действия локальная. Desktop/mobile проверяются отдельно, особенно 320–360 px, 650 px, 950 px, 960–1199 px и 1200+ px. Текущие Zero Block имеют свои брейкпоинты (360/1200), ME602A переключается в select около 960 px.

## 11. Известные ограничения / следующий backlog

- Шаг необязательных уточнений удалён по новой схеме клиники. При изменении требований возможно добавление новых вопросов с явной таблицей соответствий.
- ЖКТ не представлен в схеме и не должен отображаться в пользовательском выборе. При изменении схемы потребуется изменить правила и темы интерфейса.
- На 18.11.2026 реализовано DOM-чтение названия, двух цен и состава через точные elem_id исходного Zero Block. Исторические цены/состав в JSON сохраняются, но не используются T123. Изменение цены в существующем слое требует только публикации Tilda; изменение структуры слоя требует правки source-map, сборки и публикации T123.
- Нет интеграции выбора с формой заявки.
- Нет доказанного end-to-end теста в браузере опубликованного сайта. Снимки и тестирование адаптива нужно проводить по реально загруженной странице.
- Возрастные границы программы «Здоровый подросток» и «Половое созревание» содержат 18 лет, а другие детские программы завершаются в 17 лет. Сверяй конкретные метаданные при изменениях.
- Квиз не заменяет исходные карточки и не включает CRUD для чекапов. Текущий набор — 16 программ на странице /checkup.

## 13. Live Zero Block data binding (18 ноября 2026)
