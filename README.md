# Comfort Clinic · Check-up Quiz

Интерактивный квиз подбора программ обследования для [Comfort Clinic](https://comfortclinic.kz/checkup). Проект встроен в **Tilda T123** и использует существующий каталог из 16 чекапов, расположенный ниже на той же странице. Код написан на чистых HTML, CSS и JavaScript: без npm-зависимостей, сборщика, сервера, API и передачи ответов на сторонние ресурсы.

> **Статус на 18.11.2026:** опубликован квиз T123 **5520789203** с автоматическим чтением текущих названий, цен и состава из исходных 16 Zero Block. Сохранение, точное совпадение с GitHub, сохранность всех 18 блоков, публикация и проверка публичного HTML подтверждены. 26 тестов логики прошли. Полное браузерное тестирование взаимодействий и адаптива ещё требуется. Изменения кода в GitHub не публикуются автоматически.

## Быстрый старт

1. Открой страницу «Чекапы» в Tilda. Её Page ID: **253194603** (project ID **19996296**), адрес в настройках — **/checkup**.
2. Найди существующий блок **T123**, Record ID **5520789203**. Он стоит **перед блоком вкладок**.
3. Скопируй **полное содержимое** [tilda/comfortclinic_quiz_T123.html](tilda/comfortclinic_quiz_T123.html) в поле HTML этого блока. Файл уже включает разметку, стили, скрипт и встроенную копию данных 16 программ. Отдельно подключать JSON не нужно.
4. Сохрани блок и открой предварительный просмотр, проверь клавиатуру, мобильную ширину, работу вкладок и переход к записи.
5. После проверки опубликуй страницу средствами Tilda. Публикация **не выполняется** при обновлении GitHub.

Не вставляй квиз в общий Header/Footer: иначе он появится на других страницах. Не добавляй второй ME602A с теми же ID программ.

## Пользовательский сценарий (по схеме клиники от 12 ноября 2026)

Теперь четыре экрана: **1. Пол → 2. Возраст → 3. Направление → 4. Результат**. Отдельный шаг с уточнениями удалён: в присланной схеме его нет и он не влиял на рекомендации.

Возрастные ветки без пересечений: **0–17** (детские), **18–34**, **35–100**. При поиске рекомендаций дополнительно соблюдаются возрастные границы каждой конкретной программы (`ageMin`, `ageMax`). У детей отображаются строго четыре направления из схемы: «Детские чекапы», «Щитовидная железа», «Лишний вес», «Общий профиль». У взрослых отображаются «Щитовидная железа», «Лишний вес», «Общий профиль» и «Гинекология» или «Урология» согласно полу. Отсутствующее в схеме направление ЖКТ **не показывается**.

### Матрица рекомендаций

Коды программ определены в [data/recommendation-rules.json](data/recommendation-rules.json). Текущие правила:

| Пол, возраст | Направление | Очередность |
| --- | --- | --- |
| Женщина, 18–34 | Гинекология / Щитовидная / Лишний вес / Общий | A B C / G F B / G F / G F B |
| Женщина, 35+ | Гинекология / Щитовидная / Лишний вес / Общий | A B C / G F B / F I H / F B C |
| Мужчина, 18–34 | Урология / Щитовидная / Лишний вес / Общий | D E / G F D / G F / F D E |
| Мужчина, 35+ | Урология / Щитовидная / Лишний вес / Общий | D E / G F D / F I H / F I D |
| Дети, 0–17 | Детские / Щитовидная / Лишний вес / Общий | K1 K4 K5 / K6 K3 K7 / K1 K3 K7 / K1 K3 K4 |

Каждая ветка выводит **до 3 программ в заданном порядке**, но только если конкретная программа разрешена указанному возрасту и полу в каталоге. Например, для ребёнка младше 10 лет в ветке детской щитовидной железы все K6/K3/K7 могут оказаться недоступны, и система покажет подходящие программы общего профиля.

Если у выбранного направления нет подходящих по возрасту программ, применяется **fallback** на общий профиль той же группы/пола. Непредусмотренные схемой направления отсутствуют в меню. Добавление нового направления в будущем потребует дополнения матрицы и списка вариантов интерфейса; автоматического появления категории по полю `topic` нет.

**Результат:** до трёх карточек программ и четвёртая карточка **«Не нашли подходящий чек-ап? Подберём!»** со ссылкой на WhatsApp клиники. Отдельные кнопки самостоятельного выбора и обсуждения удалены.

## Алгоритм результата

1. Определить возрастную группу по точному возрасту.
2. Взять очередь кодов из матрицы клиники для пола + возрастной группы + направления.
3. Сопоставить буквенные коды с существующими Record ID через `rules.codes`.
4. Удалить недоступные по `ageMin`/`ageMax`/полу программы, сохранив порядок.
5. Если подходящих нет, применить матрицу направления `general` той же группы (fallback).
6. Вывести до трёх подходящих карточек + карточку связи с клиникой через WhatsApp.

Это каталожные рекомендации по правилам клиники, а не система постановки диагноза.

## Кнопки и интеграция с Tilda

- **Посмотреть программу:** переключает вкладку штатного блока **ME602A / t1281**, использует хеш вида **#!/tab/5299319803-3**, затем ищет соответствующий **#rec<recordId>** и пытается прокрутить страницу к карточке. Не скрывает напрямую существующие Zero Block.
- **Записаться:** ведёт в popup **#zapis-checkup**. Перед внедрением убедиться, что этот якорь реально существует на опубликованной странице.
- **Не нашли подходящий чек-ап? Подберём!:** четвёртая карточка предлагает открыть WhatsApp по заданной ссылке `https://wa.me/77713953828?...`. Она не передаёт ответы квиза автоматически. Две нижние кнопки «Выбрать чекап самостоятельно» и «Обсудить выбор с клиникой» удалены. На карточках программ остаются действия «Посмотреть программу» и «Записаться» без значка стрелки.
- **Назад / Начать заново:** возвращают к предыдущему шагу / очищают ответы.
- Ответы и название выбранной программы **не передаются автоматически** в заявку. Кнопка открытия popup **не означает отправки** формы.

Порядок вкладок: **1 Женский · 2 Мужской · 3 Общий · 4 Детский**. При изменении нативных вкладок, их Record ID или связей li_blocks необходимо обновить ссылки в квизе.

## Дизайн и адаптивность

Квиз использует отдельные селекторы **#cc-quiz / .ccq***, чтобы минимизировать конфликты со стилями Tilda. Палитра: основной зелёный **#004341**, розовый акцент; шрифты наследуются от сайта. Адаптивность предусмотрена приблизительно на **950 px** и **650 px**, плюс системная настройка уменьшения анимации. Проверка наличия CSS не заменяет визуальный просмотр в браузере.

## Обновление цен и программ

**Для обычного изменения цены, старой цены, названия или списка услуг:** открой нужный исходный Zero Block в Tilda, измени текстовые слои и опубликуй страницу `/checkup`. Квиз использует `textContent` этих слоёв при показе результатов. **Редактировать GitHub и T123 не нужно**, если сами слои и их идентификаторы сохранились.

**Если текстовый элемент был пересоздан или появился новый чекап:** обнови `data/tilda-source-map.json` (точные `elem_id`); для нового чекапа добавь его `recordId` и возраст/пол в `data/checkups.json`, а код программы и место в выдаче в `data/recommendation-rules.json`. Затем:

```bash
npm run build
npm test
```

После пересборки обнови существующий T123 `5520789203` и опубликуй страницу. Новая программа не попадает в рекомендации автоматически без явного правила матрицы.

В `data/checkups.json` теперь только техническая информация и справочное имя; **цен и состава там нет**. Матрица рекомендаций остаётся в JSON, но значения коммерческих полей считываются с уже опубликованной страницы. Если в Zero Block пропала цена или изменился ID слоя, квиз не показывает старую цифру: появится «Стоимость в программе» со ссылкой на полную карточку.

## Проверки и ограничения

~~~bash
node scripts/verify.mjs
~~~

Скрипт проверяет корректность данных, уникальность ID, суммы выгоды, соответствие встроенного справочника JSON, отсутствие нежелательных пользовательских заглушек, наличие четырёх экранов и четвёртой карточки и основных ссылок. Это **статические проверки**: они не подтверждают работу мобильного dropdown Tilda, скроллинг, popup записи или качество верстки на опубликованном сайте.

Рекомендуемые ручные прогоны: женщина 28 лет / гинекология; мужчина 42 года / урология; ребёнок 8 лет / общий профиль; ребёнок / щитовидная железа (fallback); граничные значения 0, 6, 7, 17, 18, 35, 100; пустой ввод, назад, сброс, мобильная версия, открытие конкретного Zero Block и общей формы.

## Конфиденциальность и обслуживание

Ответы обрабатываются в браузере и не сохраняются скриптом в localStorage/cookie, не отправляются fetch/XHR. Это не аудит всех сторонних скриптов Tilda, аналитики или расширений браузера. В репозитории нет API-токенов; подключение Tilda MCP и учётные данные не должны храниться в исходниках.

Изменения в этом репозитории **не затрагивают** уже опубликованную страницу до отдельной операции обновления T123 и публикации.

## Актуальные цены и состав без дублирования

**Реализация от 18.11.2026:** текстовые данные **не берутся из checkups.json** и **не встраиваются в T123**. HTML содержит только Record ID/возраст/вкладки/матрицу и идентификаторы конкретных текстовых слоёв из `data/tilda-source-map.json`.

При открытии экрана результатов JavaScript ищет в **уже загруженной странице** каждый оригинальный `#rec<recordid>`. Для названия, текущей цены, старой цены и отдельных строк состава используются **строго адресные CSS-селекторы** вида:

```js
const text = document.querySelector('#rec5336877803 [data-elem-id="81024965647"] .tn-atom')?.textContent;
```

Это работает без Tilda MCP, без Render и без сетевых запросов: все 16 Zero Block уже присутствуют в DOM страницы, включая скрытые штатными вкладками Tilda. Модель фильтра рекомендаций по-прежнему использует `ageMin/ageMax` и `recommendation-rules.json`.

**Если изменена цена/название/услуга внутри существующего текстового слоя:** достаточно опубликовать страницу Tilda и перезагрузить её; квиз извлекает новую информацию. **Если слой удалён, пересоздан, перенесён в другой Record ID или новая программа добавлена:** требуется обновить `data/tilda-source-map.json`, а для новой программы ещё и каталог/матрицу, выполнить `npm run build && npm test`, затем обновить T123 и опубликовать.

**Безопасность отображения:** если цена не найдена или не распознана, квиз показывает «Стоимость в программе», а не устаревшую цифру. Если строки состава недоступны, предлагает открыть исходную программу. Скрипт не запрашивает непубличную информацию и не изменяет исходные Zero Block.

Техническое ограничение: читатель должен исполняться на той же странице, где Tilda загрузила все 16 блоков. При переносе на другую страницу потребуется другой источник данных. Проверка корректности чтения на всех устройствах проводится отдельно; статические тесты подтверждают сборку и правила, но не весь браузерный сценарий.
